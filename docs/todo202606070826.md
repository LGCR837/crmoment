## CRMoment

> 核心原则：够用、简单、公开接口免登录。用户少，本地存储图片。

---

### 一、整体架构

- **环境**：PHP + MySQL（免费虚拟主机）
- **存储**：站点 `/uploads/avatars/`（头像）、`/uploads/posts/`（动态图片）
- **认证**：PHP Session（`user_id` 存在 session 中即登录）
- **接口风格**：简单 REST，返回 JSON
- **无需认证的接口**：查看动态列表、查看单条动态、查看个人主页、查看评论列表
- **需要认证的接口**：发布动态、上传图片、评论、点赞、关注（可选）、通知相关

---

### 二、数据库（极简版）

仅保留 5 张核心表：

| 表名 | 字段 |
|------|------|
| `users` | id, username, avatar, bio, password_hash, created_at |
| `posts` | id, user_id, content, images(JSON), likes_count, comments_count, created_at |
| `comments` | id, post_id, user_id, parent_id, content, created_at |
| `likes` | user_id, post_id (联合主键) |
| `notifications` | id, user_id, type, actor_id, post_id, is_read, created_at |

---

### 三、接口列表

**基地址**：`https://crmoment.ccwu.cc/app/`  
所有接口返回格式：

```json
// 成功
{ "code": 0, "message": "ok", "data": {...} }

// 失败
{ "code": 1, "message": "错误原因" }
```

---

#### 1. 用户相关

| 接口 | 方法 | 需要登录 | 说明 |
|------|------|----------|------|
| `/auth/register` | POST | 否 | 注册：`{username, password}`（可省略邮箱） |
| `/auth/login` | POST | 否 | 登录：`{username, password}`，返回用户信息并写入 session |
| `/auth/logout` | POST | 是 | 退出 |
| `/user/:id` | GET | 否 | 获取用户公开信息（含动态数量） |
| `/user/me` | GET | 是 | 获取当前登录者信息 |

**注册/登录返回示例**：
```json
{ "code": 0, "data": { "id":1, "username":"alice", "avatar":"/uploads/avatars/1.jpg" } }
```

---

#### 2. 动态相关（大量免登录）

| 接口 | 方法 | 需要登录 | 说明 |
|------|------|----------|------|
| `/posts` | GET | 否 | 动态列表（按时间倒序），参数 `?page=1&size=20` |
| `/posts/:id` | GET | 否 | 单条动态详情（含评论列表） |
| `/posts` | POST | 是 | 发动态：`multipart/form-data`，字段 `content`，`images[]`（最多9张） |
| `/posts/:id` | DELETE | 是（作者） | 删除动态 |
| `/posts/:id/like` | POST | 是 | 点赞 |
| `/posts/:id/like` | DELETE | 是 | 取消点赞 |

**免登录调用示例**：`GET /app/posts?page=1` → 任何人可看。

---

#### 3. 评论相关

| 接口 | 方法 | 需要登录 | 说明 |
|------|------|----------|------|
| `/posts/:id/comments` | GET | 否 | 获取一级评论列表，参数 `?page=1` |
| `/posts/:id/comments` | POST | 是 | 发表评论：`{content, parent_id?}` |
| `/comments/:id` | DELETE | 是（作者） | 删除评论 |

**免登录查看评论**：`GET /app/posts/123/comments`

---

#### 4. 通知相关（需登录）

| 接口 | 方法 | 需要登录 | 说明 |
|------|------|----------|------|
| `/notifications` | GET | 是 | 获取我的通知列表（分页） |
| `/notifications/unread` | GET | 是 | 获取未读数量 |
| `/notifications/read` | PUT | 是 | 全部标记已读 |

---

#### 5. 文件上传（需要登录）

| 接口 | 方法 | 需要登录 | 说明 |
|------|------|----------|------|
| `/upload/image` | POST | 是 | 单独上传单张图片，返回 URL。用于发动态前预上传（也可以直接在发动态时附带图片） |

简化方案：发动态时直接附带 `images[]`，后端自动保存。不提供单独的 `/upload/image` 也可以。

---

### 四、无需认证的接口汇总（公开接口）

任何人（包括未登录游客）可以：

- `GET /app/posts` — 浏览动态列表
- `GET /app/posts/:id` — 查看某条动态详情
- `GET /app/user/:id` — 查看他人主页
- `GET /app/posts/:id/comments` — 查看评论

这些接口**不校验 session**，数据库查询时也不需要用户身份（但可额外返回当前用户是否点赞，如果没登录就不返回这个字段）。

---

### 五、登录与认证说明

- 登录成功后，后端设置 `$_SESSION['user_id']`，前端不需要额外 token。
- 后续需要登录的接口，后端检查 `session` 是否存在 `user_id`，不存在返回 `{code:1, message:"请先登录"}` 和 HTTP 401。
- Cookie 会自动携带，无需前端手动处理。

---

### 六、文件存储规则（极简）

- 头像上传：`POST /app/user/avatar`（需登录），文件存到 `/uploads/avatars/{user_id}.jpg`（覆盖旧图）
- 动态图片：发布动态时上传的图片存到 `/uploads/posts/{year}/{month}/{随机名}.jpg`
- 允许格式：jpg, png, gif, webp，最大 5MB
- 删除动态时，后端读取 `images` 字段中的路径，删除对应物理文件

---

### 七、简易通知触发规则

- 评论别人的动态 → 给动态作者发 `comment` 通知
- 回复别人的评论 → 给原评论作者发 `reply` 通知
- 点赞别人的动态 → 给动态作者发 `like` 通知
- 自己操作自己不发通知

通知表插入记录后，前端轮询 `/notifications/unread` 获取红点数量。

---

### 八、扩展：关注功能（可选，但简单可加）

若需要“首页只显示关注的人”，可加一张表 `follows`（follower_id, following_id），然后 `/app/posts` 增加参数 `?type=follow` 需登录才返回关注流。

该接口可设计为**需要登录**，因为依赖当前用户的关注列表。

---

以上即为简化版后端设计，没有复杂的 WebDAV、没有过度优化，适合快速实现。
